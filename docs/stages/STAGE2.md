# Stage 2 — Acquisition Evidence and Record Screening

## Purpose and boundary

Stage 2 verifies provider files, screens available records against the frozen spatial domain, audits duplicate lineages and measurement support, and maintains the live acquisition-status overlay. It does not construct bloom outcomes, decide observation adequacy, harmonize taxa, or inspect CMEMS PhyC.

The scientific rules remain frozen in `docs/DATASET_SYSTEMATIC_SEARCH.md`, `docs/OUTCOME_AND_LIFEFORM_PROTOCOL.md`, and `docs/STAGED_WORK_PLAN.md`. This file is the single operational description of Stage 2.

## Directory contract

| Location | Contents | Rule |
|---|---|---|
| `scripts/00_downloads/stage2/` | exact provider requests, raw downloads, manual-export intake, and active-run registration | the only Stage 2 scripts allowed to create or register raw evidence |
| `scripts/02_stage2/control/` | frozen work order, live status, and validation gate | never contacts providers |
| `scripts/02_stage2/wfs/` | registration and screening of the archived EMODnet WFS runs | operates only on explicitly supplied or pinned existing run directories |
| `scripts/02_stage2/datasets/` | provider-specific inventory, spatial screening, duplicate resolution, and summaries | reads immutable raw files and generates derived results |
| `data/raw/stage2/` | immutable provider responses and files in the required external store | never edited, replaced, or silently reacquired |
| `data/interim/` | large generated row-level screening and duplicate tables | rebuildable and ignored where appropriate |
| `metadata/stage2/control/` | generated frozen routing artifacts and live workflow status | distinguishes the prospective all-`not_started` baseline from current progress |
| `metadata/stage2/acquisition/` | generated active-run pins, manifests, and intake evidence | checksum bridge to immutable raw files |
| `metadata/stage2/screening/` | generated location, variable, duplicate, method, and dataset decisions | never edited manually |
| `metadata/stage2/inventory/` | complete generated file inventory | one row per Stage 2 file, including raw evidence |
| `outputs/logs/stage2_contract_validation_*.log` | dated offline-gate records with checksums, tests, R version, and session information | generated by the Stage 2 gate |

## Development and publication commands

Validate the consolidated Stage 2 state from existing files:

```sh
Rscript scripts/02_stage2/00_run_stage2.R
```

This is an offline replay gate. It rebuilds deterministic control outputs, refreshes the calculated status, runs the Stage 2 tests, writes a log, and regenerates the inventories. It never calls an acquisition script and never downloads a file.

Provider acquisition is deliberately separate. Run a script in `scripts/00_downloads/stage2/` only for an authorized new or resumed acquisition. Each script retains its exact provider request construction and writes append-only raw evidence. The ordinary gate instead uses the existing active-run pins and checksums.

## Script groups and result ownership

1. `control/00_initialize_contract.R` generates the 19-item frozen work order, the unresolved WFS queue, and the contract-freeze record from Stage 1 inputs. `control/02_build_access_dispositions.R` generates the contact/unavailable register and distinguishes required access emails from optional metadata requests.
2. `wfs/00_register_geometry_run.R` and `wfs/02_register_metadata_run.R` checksum-pin explicitly named existing raw runs. `wfs/01_screen_geometry.R` and `wfs/03_resolve_survivors.R` generate all WFS screening results.
3. The DS02, DS06, and DS26 inventory scripts generate their variable, record, event, method, duplicate, and output registries. Their companion resolve and summarize scripts generate the contract-level dispositions.
4. The DS03, DS04, DS05, DS07, DS09, DS10, DS11, DS16, and DS24 screen scripts generate exact location/record summaries from existing provider files. The `02_summarize_*` scripts generate their dataset-level screening summaries.
5. `02_summarize_ds15_ds22_screening.R` generates secondary/comparator dispositions from the existing acquired reference files.
6. `02_screen_ds12_cpr.R` verifies and screens the public CPR DwC-A at event level, preserving PCI and taxon linkage while limiting it to Tier D/E recurrence corroboration.
7. `02_screen_ds27_ferrybox.R` decodes every pinned NetCDF through an R-controlled `ncdump` bridge, retains chlorophyll fluorescence as Tier E, and excludes the separately archived pCO2-only collection from phytoplankton evidence.
8. `control/01_refresh_acquisition_status.R` derives current work state only from generated evidence. `control/99_validate_stage2.R` owns the offline gate and validation log.
9. `scripts/00_traceability/01_build_stage_file_inventory.R` generates `metadata/stage2/inventory/file_inventory.csv`, the cross-stage summary, and the unresolved-artifact report.

Dataset scripts are intentionally small and can be rerun separately after a relevant input or code change. A script must verify its active pin and raw checksums before using provider content. Verified registry paths can be migrated to the consolidated layout only when the registered output checksum still matches.

## Current gate state

The calculated state is `metadata/stage2/control/acquisition_status.csv`; do not copy workflow counts from this description. A `pending` scientific screening decision remains pending and is not a negative observation, but it does not make Stage 2 work incomplete when actual records have already been acquired and screened. Later coverage, method, overlap, and biomass audits own those final eligibility decisions.

The ranked work order is fully dispositioned when the generated status contains only `complete` and `unavailable`. DS08, DS23, and DS28 are temporarily unavailable because usable access requires provider email; their reasons, present consequences, evidence paths, and revisit triggers are generated in `metadata/stage2/control/access_dispositions.csv`. Five additional contact-only candidates outside the ranked work order are recorded there for later coverage-risk interpretation. Missing access is never represented as a zero-row biological result.

DS12 is screened from its existing public CPR DwC-A and retained only as Tier D/E PCI and taxon recurrence evidence. Its provider email is an optional effort-metadata enhancement and does not block Stage 2. DS27 is screened across every pinned FerryBox NetCDF file through the documented R-controlled `ncdump` bridge; chlorophyll fluorescence is a Tier E comparator, not carbon, and the separate pCO2-only collection is excluded from phytoplankton evidence. Exact counts and checksums remain in their generated summaries and output registries.

Closing this Stage 2 work-order gate does not resolve later scientific eligibility. Observation adequacy, CMEMS overlap, method compatibility, biomass conversion, recurrence, and independence remain owned by Stages 3–5 and retain unknown or pending states where appropriate.

## Traceability and publication use

Every generated Stage 2 result must identify a version-controlled producer; every raw payload must reconcile to a manifest checksum or an explicitly registered historical intake. The historical `data/raw/stage2/downloaded_files_inventory.md` is immutable but superseded by the generated CSV inventory.

DS04 is acquired by `scripts/00_downloads/stage2/11_acquire_ds04_plet_bsh.R` as the validated `BSH_Phyto_Zoo_abundance` payload. DS22 is acquired by `scripts/00_downloads/stage2/22_acquire_ds22_peg_bvol.R` as the provider PEG_BVOL archive containing `PEG_BVOL2026.xlsx`. These Stage 2 active pins are the only authoritative inputs for downstream stages; historical malformed or schematic-only raw runs remain immutable but inactive.

Use the generated acquisition manifests, screening summaries, status overlay, inventories, and validation logs for manuscript numbers and decisions. Do not transcribe counts from this description. Stage 2 provisional tiers are routing evidence only; final eligibility, recurrence, and reference construction belong to later observation-only stages.
