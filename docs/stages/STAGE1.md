# Stage 1 — Reproducible Systematic Search

## Purpose and boundary

Stage 1 identifies potentially eligible in-situ datasets and produces the named acquisition work order for Stage 2. It operates only on dataset-level catalogue evidence. It does not decide record-level eligibility, construct bloom outcomes, or inspect CMEMS PhyC.

The scientific eligibility rules remain frozen in `docs/DATASET_SYSTEMATIC_SEARCH.md` and `docs/STAGED_WORK_PLAN.md`. This file is the single operational description of the executed Stage 1 workflow.

## Directory contract

| Location | Contents | Rule |
|---|---|---|
| `scripts/00_downloads/stage1/` | one programmatic search per source family and the append-only EMODnet WFS search | the only Stage 1 scripts allowed to create raw responses |
| `scripts/01_stage1/` | compile, qualify, validate, and orchestrate Stage 1 | reads pinned responses; never downloads raw data |
| `data/raw/search_runs/SEARCH-*` | immutable provider responses, request manifests, run summaries, and logs | never moved, overwritten, or manually edited |
| `metadata/stage1/input/` | preserved discovery input that predates executable search | input evidence, not an API-search result |
| `metadata/stage1/search/` | generated run pins, query log, candidate registry, flow counts, recall, and append-audit results | rebuilt from scripts and pinned raw evidence |
| `metadata/stage1/qualification/` | generated DS crosswalk, ranked acquisition shortlist, unavailable candidates, and access-request register | Stage 2 handoff |
| `metadata/stage1/inventory/` | generated file-level inventory | one row per Stage 1 file, including raw evidence |
| `outputs/logs/stage1_validation_*.log` | dated validation records with checksums, tests, R version, and session information | generated by the Stage 1 gate |

## Commands

Rebuild and validate all generated Stage 1 results from the currently pinned immutable responses:

```sh
Rscript scripts/01_stage1/00_run_stage1.R
```

Execute a new complete search only when the protocol requires a dated search update:

```sh
Rscript scripts/00_downloads/stage1/00_run_searches.R
```

The search command creates new append-only raw run directories and updates the active-run registry. It is not part of an ordinary deterministic rebuild.

## Execution order and outputs

1. `01_compile_candidate_registry.R` verifies pinned run configuration and response checksums, parses every catalogue record, and generates `metadata/stage1/search/` results.
2. `02_build_ds_crosswalk.R` resolves the narrative DS register against archived evidence and generates `metadata/stage1/qualification/` results.
3. `99_validate_stage1.R` proves byte-identical regeneration, runs Stage 0 dependencies and Stage 1 tests, writes a validation log, and refreshes the complete file inventory.
4. `scripts/00_traceability/01_build_stage_file_inventory.R` reads acquisition manifests and generates `metadata/stage1/inventory/file_inventory.csv` plus the cross-stage summary and unresolved-artifact report.

The authoritative Stage 2 work-order input is `metadata/stage1/qualification/acquisition_shortlist.csv`. Catalogue-level `pending` is not an eligibility decision.

## Traceability contract

Every generated Stage 1 result must name a version-controlled producer script. Every raw response must have a recorded checksum in an immutable manifest or a checksum calculated by the inventory script for diagnosed preflight evidence. The inventory records file category, path, producer, script references, byte size, SHA-256 route, Git state, immutability, and traceability state.

The gate fails when a generated or raw Stage 1 artifact is unresolved, a pinned configuration no longer matches its raw run summary, pagination does not reconcile, a known-item benchmark is missing or screened out, a register entry is undiagnosed, or a generated result changes when rebuilt from unchanged evidence.

## Publication use

Use generated registries and validation logs for manuscript counts, flow diagrams, search dates, provider versions, and exclusions. Do not transcribe counts from this description. The current calculated state is in `metadata/stage1/search/search_flow.csv`, `metadata/stage1/qualification/ds_crosswalk.csv`, and `metadata/stage_file_inventory_summary.csv`.
