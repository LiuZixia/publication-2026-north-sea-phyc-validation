### Stage 1 defects repaired this session

1. **Two benchmarks were screened out.** The dataset-metadata biological screen matched only `phytoplank`, while PLET titles abbreviate: DS02 `RWS_Fpzout_2000-2019_phyto` and DS04 `BSH_Phyto_Zoo` were therefore marked `excluded` as outside biological scope. Known-item recall still reported them found, because it only tested presence in the registry. The screen now recognises the abbreviated and clade-level forms, and both benchmarks are `pending`.
2. **Title identity depended on capitalisation.** `tolower(gsub("[^a-z0-9]", "", title))` applied the character class before folding case, so every uppercase letter was deleted rather than lowercased. The previous session's SmartBuoy alias rule could never match and had no effect. Folding now precedes stripping.
3. **A shared provider DOI merged distinct observatories.** PLET publishes eight separate Marine Scotland series under one DOI (`10.17031/1637`), so Loch Ewe, Scalloway, Scapa, and Stonehaven were reported as a single dataset family and DS16 Stonehaven appeared as a duplicate of Loch Ewe. A DOI that one source attaches to more than one distinct title is now treated as a collection DOI and excluded from identity grouping. Unique dataset families moved from 21,114 to 21,274.
4. **The GBIF geographic screen had no effect.** It was an inclusion term in a disjunction that any phytoplankton dataset satisfied through the biological pattern, so all GBIF rows passed regardless of stated geography while the previous handoff reported out-of-domain results as filtered. The dead term is removed and replaced by an explicit `geographic_screen_state` column on every row.
5. **Non-ASCII rows were silently unmatchable.** Under the C locale, provider strings carrying non-ASCII characters (for example the NLWKN German provider names) were marked as unknown encoding, so `perl = TRUE` matching declined to match them and emitted only a warning. A benchmark could have gone unrecalled without any failure being raised. Provider text is now marked UTF-8 at parse time.
